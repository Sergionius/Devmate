# 0006. Versioned backup envelope without API keys

- **Status:** Accepted
- **Date:** 2026-11

## Context

Users move between devices. The catalog alone (existing JSON import) does
not carry progress; a full backup needs progress, preferences, and AI
endpoint settings — but must never carry API keys.

## Decision

Backups use an envelope: `format: "devmate-backup"`, integer `version`,
`exportedAt`, plus `catalog` (the existing topics JSON), `progress.scores`
(question ID → 5|10), `preferences`, and `ai` (baseUrl/model only).

Replace-restore keeps topic/question IDs from the file
(`TopicCatalog.restoreJson`) so progress stays valid; merge-restore adds
topics with fresh IDs and keeps the better score for questions that already
exist on the device. Envelope parsing is strict about identity and version,
tolerant about individual entries.

## Consequences

- Cross-version forward compatibility: unknown higher versions are rejected
  with a clear message; unknown entry values are dropped, not fatal.
- New-question progress does not survive merge (IDs are regenerated by the
  title-matching import path) — documented in the UI and in
  `docs/plans/2026-11-*` design notes.
